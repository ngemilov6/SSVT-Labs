Design Report:
The implementation calculates the number of surviving mutants by executing property 
checks against mutated outputs of the function under test. The core function, 
countSurvivors, iterates through the requested number of mutants by leveraging 
sequenceA over a replicated list of IO actions. To prevent equivalent mutants from 
artificially inflating the survivor count, the generateDifferentMutant function is 
designed to recursively apply mutators until the resulting output strictly differs 
from the original valid output. The code utilizes explicit monadic binding (>>=) and 
functor mapping (<$>) to sequence the random generation and property evaluation without
relying on do blocks, keeping the logic concise. The results are then filtered to count 
how many mutants successfully passed every supplied property.

Effect of Using Different Mutators and Properties:
The survival rate of mutants is heavily dependent on the specific pairing of mutators 
and properties. Structural mutators, such as addElements or removeElements, easily trigger 
failures in properties that enforce size constraints, like prop_tenElements, resulting in 
fewer survivors. However, if these structural mutators are evaluated exclusively against 
mathematical properties, like prop_moduloIsZero, they may produce more survivors if the randomly 
injected elements happen to satisfy the modulo condition. Conversely, highly restrictive properties, 
such as prop_linear, which strictly bounds the entire numerical sequence, will consistently kill almost 
all mutants generated by value-shifting mutators. A mutant only survives if the property suite lacks 
the specific assertions necessary to detect that mutator's specific class of output manipulation.
