Exercise 5
Time spent: 90min
Design Report:
The implementation discovers property conjectures by evaluating all supplied properties against a generated collection of mutants. 
The Conjecture data type represents two kinds of relationship: Equivalent p1 p2 indicates that two properties have identical mutation-testing results, 
while FollowsFrom target antecedents indicates that the listed antecedent properties jointly imply the target property.
The findConjectures function is responsible for collecting mutation results and deriving the conjectures. 
It generates one result row per mutant using generateMutationResults. 
Each row contains a Boolean value for every property, representing its result for that mutant. 
The implementation then compares these rows to identify relationships between property indices.
equivalentProperties checks whether two properties always produce the same Boolean result across all generated mutants. 
If so, the properties kill and survive the same mutants and are reported as equivalent.
impliedBy checks whether a set of antecedent properties implies a target property. 
For every mutant, if all antecedents hold, then the target must also hold. minimalImplicationSets considers all 
subsets of the other properties and retains only implication sets that do not have a strict subset 
which also implies the target. This ensures that only minimal antecedent sets are reported.
We also add prop_tenElements2, which is intentionally identical to the first ten-elements property.
After adding the additional property, we adjusted the implication condition to have at least 2 antecedents.
Otherwise 1 == 2 would also appear as 1 => 2 and 2 => 1, which is unwanted.
We also see for this Exercise that the conjectures generated are of course closesly related to the minimal subset of properties.
