Design Report:
1. We defined isDerangement using two properties:
    - that the two lists have to be permutations of each other, using the implementation from Exercise4.
    - that none of the elements at the same index should have the same value, implemented using zipWith (/=).
2. deran is implemented by filtering the list of all permutations with the property isDerangement.
    In the base case it returns an empty list. We decided to throw an error for negative inputs,
    as we are only looking at derangements of the positive integers [0..(n-1)] for n>0.
3. We created several properties:
    - prop_deran_valid: Does not test isDerangement but checks whether all elements of deran are actually derangements of the base list [0..(n-1)].
    - prop_derangement_symmetric: checks that if xs is a drangement of ys, then ys is also a derangement of xs.
    - prop_derangement_no_fixed_points: checks that if xs and ys are derangements that then also the property that no
        values at the same index are equivalent.
    We also made a list of manual test cases, that cover proper derangements, identical lists, singletons, different lengths and elements, and duplicates.
    For this, we made a generator which selectes elements from the test cases.
4. Ordered List of properties on isDerangement
The two properties are not comparable. If the function is confirmed to be symmetrial, that does not imply that there are no fixed points, and vice versa
no fixed points does not imply that the function is symmetrical.
5. We can automate the test process by generating permutations and derangements, similar to Exercise4.
This was adjusted to match the lists being permutations of [0..(n-1)]. The same structure using gen_perms, gen_perm, genList, makePerm and genSmallNat as before was used.


Test Report:
For the tests, we assumed that our functions from previous exercises were correct: isPermutation + helpers and the generators.
Inputs are generated using the same generator of permutations as before for the automatic tests, and selected from a manual set of test cases.
These only cover a small portion of the input domain. The manual test cases cover some edge cases.
As all tests pass 100 times, with no reduction due to discarded tests, we have reason to conclude that the functions likely do satisfy the properties they were tested against.
It does not, however, prove that the function is fully correct, as the full domain was not covered by the test coverage.
